# Debutuuru: notes for AI assistants and contributors

A Rust + Tauri desktop toolbox for developers. It starts as a git client
(GitKraken-like) and grows into terminals, task runner, GitHub/GitLab,
containers… It runs on Windows (including repos inside WSL) and on Linux, and
opens from any terminal.

Read `docs/ARCHITECTURE.md` (design + roadmap) and `docs/VERSIONING.md` first.

## Layout

| Path | Role |
| --- | --- |
| `crates/debutuuru-core` | git operations through the system `git` binary, worktrees, graph lanes, path/WSL parsing. No transport. |
| `crates/debutuuru-protocol` | Agent wire protocol (NDJSON), `PROTOCOL_VERSION`, method names and param types per module. |
| `crates/debutuuru-agent` | `Agent` with `Module`s (git…), stdio server, `StdioClient`, `Transport` trait. |
| `crates/debutuuru-cli` | `debutuuru` binary: `open`, `agent --stdio`, inspection commands. |
| `apps/desktop/src-tauri` | Tauri shell: routes the `rpc` command to the right agent. |
| `apps/desktop/src` | React + Vite + TS UI; one folder per module under `src/modules/`. |
| `apps/desktop/src/bindings` | **Generated** TS types (ts-rs). Never edit by hand. |

## Rules

- **The UI never runs git or touches repos.** Everything goes through
  `rpc(repo, "module.method", params)` → desktop shell → agent. That's what
  makes WSL repos work (the agent runs inside WSL).
- **New tool = new agent `Module`** with namespaced methods
  (`term.*`, `forge.*`, …), param/result types in `debutuuru-protocol`
  (with `#[derive(TS)] #[ts(export)]`), and a UI folder in `src/modules/<name>`.
- **Protocol changes are additive** within a `PROTOCOL_VERSION` (new methods,
  new optional fields). Breaking changes bump `PROTOCOL_VERSION`; module changes
  bump that module's `MODULE_VERSION`.
- **UI colors come only from theme tokens** (`var(--bg-panel)`, `var(--text-muted)`,
  `var(--lane-N)`…) generated by `src/theme/generate.ts`; never hard-code a color in
  a component. Rules and token meanings are in `docs/DESIGN.md`. New presets are
  just 3 inputs (base, accent, contrast) and must keep the contrast report green.
- Settings (`src-tauri/src/settings.rs`) are versioned: additive fields are fine
  with `#[serde(default)]`; renames/removals need a `SCHEMA_VERSION` bump and a
  migration step.
- After changing any Rust type exported to TS: run `cargo test` and commit the
  regenerated `apps/desktop/src/bindings`. CI fails otherwise.
- Git: use the system `git` (respects user config, hooks, credentials). Never
  store secrets. Worktrees must keep working (`.git` may be a file).
- Commits follow **Conventional Commits** (`feat:`, `fix:`, `feat!:`…). They
  drive versions and the changelog through release-plz. One product version
  lives in the root `Cargo.toml`; never bump versions by hand.
- Verify before claiming: run things and measure on the real machine, and
  search before recommending a library. Don't silently deviate from decisions
  recorded in `docs/ARCHITECTURE.md`; propose a change instead.

## Commands

Node is managed with fnm (`.node-version`). In non-interactive shells load it
first: `eval "$(fnm env --shell bash)"` (bash) or
`fnm env --shell powershell | Out-String | Invoke-Expression` (PowerShell).

```bash
cargo test --workspace                       # Rust tests + regenerate TS bindings
cargo clippy --workspace --all-targets -- -D warnings
cd apps/desktop && npm ci && npm run build   # typecheck + bundle UI
cd apps/desktop && npm run tauri dev         # run the app with hot reload
cargo run -p debutuuru -- info .             # CLI
# Linux agent for WSL repos (needs `rustup target add x86_64-unknown-linux-musl`).
# Dev builds of the app find it in target/ automatically.
cargo build -p debutuuru --target x86_64-unknown-linux-musl --release
```

- Remote operations must never override the user's SSH/credential setup by
  default (no `GIT_SSH_COMMAND`, no `-i`, no stored secrets). Prompts go
  through the askpass bridge (`crates/debutuuru-agent/src/askpass.rs`) only.
  Never log prompt answers.

Testing tips: to drive the real app UI, start the dev build with
`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222` and send
`Runtime.evaluate` over the DevTools WebSocket (Node ≥ 22 has `WebSocket`
built in). In Git Bash set `MSYS_NO_PATHCONV=1` before passing Linux paths
to `wsl.exe`. In PowerShell, run multi-line WSL commands from a script file
(`wsl -e sh <file>`), because PowerShell 5.1 mangles inner quotes.

Linux build deps: `libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev`.
